GTasks Automation - Coding Rules🏗 Modular Architecture & ExtensionSingle Source of TruthStrict Requirement: Each feature must have exactly ONE implementation.Prohibited: Creating duplicate "versioned" files (e.g., main_v2.py, dashboard_new.py).Standard: Extend existing files using parameters, flags, or configuration objects.File Naming ConventionsCase: Use snake_case for filenames.Singular: Use descriptive singular names (task_manager.py).Variants: No super_, advanced_, or enhanced_ prefixes. Use functional suffixes only if necessary (e.g., base_report.py vs task_report.py).📂 Code Organization & LogicDirectory MappingRoutes: routes/ (API/Web endpoints)Models: models/ (Data structures)Services: services/ (Business logic/Data managers)Utils: utils/ (Helpers/Exceptions)Module ResponsibilitiesFunctions: Single responsibility. Maximum 50 lines per function (excluding docstrings).Type Hints: Mandatory for all function signatures.Error Handling: Use custom exceptions from utils/exceptions.py. Log meaningful messages before raising.🤖 AI & Context ManagementIDE Behavior (Kilo Code / Continue)Modularity: Always separate business logic from UI/CLI code.Logging: Use verbose logging for automation scripts to aid remote debugging.Self-Update: If you (the AI) create a new module, you MUST update the mapping in architecture.md immediately.Context Sanitation: After a browser automation task is complete, prompt the user to run /clear or /new to purge the browser snapshots and reclaim context for coding.🌍 Browser Debugging (agent-browser)For browser operations, use the agent-browser server. This system is 93% more token-efficient than standard Playwright MCP because it uses a Snapshot + Refs mechanism.agent-browser ProtocolsSnapshotting: Always use agent-browser snapshot -i to capture only interactive elements.Stable References: Use the returned stable references (e.g., @e1, @e2) instead of generating CSS selectors or XPaths to save tokens.Commands:agent-browser navigate {url}: Navigate to a site.agent-browser click @e1: Click an element via reference.agent-browser type @e2 "text": Input text into a reference element.agent-browser wait_for_text "Success": Wait for specific UI states.Usage GuidelinesToken Preservation: Do not request full snapshots unless an interaction fails.Debugging: If the agent is confused, use agent-browser screenshot for visual verification, but be aware it uses more context tokens than text-based refs.Workspace HygienePre-flight Check: ALWAYS read context/architecture.md before suggesting structural changes.Ignore List: Ensure .kilocodeignore excludes playwright-report/ and test-results/ to prevent Kilo from indexing massive, redundant JSON artifacts.Memory Sync: After significant changes, prompt the user: "Would you like me to run 'ctx save' to sync this context?"⚠️ Anti-Patterns (The "Never" List)❌ Duplicate Files: No dashboard2.py or temp_sync.py.❌ Context Dumping: Never read more than 200 lines of a file at once if browser snapshots are in the current history.❌ Deep Nesting: Avoid if/else logic deeper than 3 levels.❌ God Modules: No single file should handle both API sync and UI rendering.
